# QuickBill 출시 체크리스트 (사용자가 직접 할 일)

코드는 준비되어 있고, 아래는 계정·돈·법적 책임이 걸려 있어서 직접 하셔야 하는 일입니다. 위에서부터 순서대로 하면 됩니다. "확인 필요"라고 적은 항목은 제가 공식 문서로 확인하지 못한 내용입니다.

## 0. 먼저 알아 둘 것

- **지금 상태**: https://quickbill-waldo5.vercel.app 에서 앱이 동작합니다. 결제 링크가 없어서 업그레이드 창에는 "아직 구매를 받지 않는다"고 표시됩니다.
- **Vercel Hobby 플랜 문제 (확인 필요)**: Vercel의 Hobby 플랜은 비상업적 개인 용도로 안내되어 있습니다. 유료 상품을 파는 사이트라면 Pro 플랜이 필요할 수 있으니, 결제를 열기 전에 Vercel 약관(Fair Use Guidelines)을 확인하세요. 정적 파일과 함수 하나뿐이라 다른 호스팅으로 옮기기도 쉽습니다.
- **검색 노출**: `*.vercel.app` 주소에서는 응답 헤더에 `x-robots-tag: noindex`가 붙어 있는 것을 확인했습니다. 검색에 노출하려면 4번(자체 도메인)이 필요합니다.

## 1. 결제 플랫폼 가입 (Lemon Squeezy 기준)

앱의 서버 검증 코드는 Lemon Squeezy 라이선스 API에 맞춰 작성되어 있습니다. Lemon Squeezy는 판매자 대신 세금 처리를 맡는 방식(Merchant of Record)이라 1인 판매자에게 부담이 적습니다. 다른 플랫폼(Gumroad, Paddle, Stripe)을 쓰려면 `api/license.js`를 바꿔야 합니다.

1. https://www.lemonsqueezy.com 에서 가입하고 스토어를 만듭니다.
2. **한국에서 가입·정산이 되는지, 수수료와 정산 방식이 어떤지 가입 전에 공식 문서로 확인하세요 (확인 필요).**
3. 상품을 만듭니다: 이름 `QuickBill Pro`, 가격 `$19` 1회 결제.
4. 상품 설정에서 **License keys**를 켜고 활성화 가능 기기 수를 정합니다(예: 3대). 이 숫자가 "기기 수" 문구의 기준이 됩니다.
5. 상품의 **공유(Share) 링크**를 복사합니다. 이것이 결제 링크입니다.
6. 스토어 ID와 상품 ID를 적어 둡니다(스토어 설정과 상품 주소에서 확인). 2번 환경변수에 씁니다.
7. 정산 계좌와 본인 확인(세금 정보)을 입력합니다.

## 2. 결제 링크·이메일·가격을 한 곳에 넣기

`invoice-pwa/config.js` 한 파일만 고치면 앱, 랜딩, 이용약관, 개인정보 페이지에 모두 반영됩니다.

```js
checkoutUrl: "1번에서 복사한 결제 링크",
supportEmail: "문의·환불용 이메일",
price: "$19 one-time",
priceShort: "$19",
refundDays: 14,
```

그다음 `invoice-pwa` 폴더에서 `node design/seo.cjs`를 실행하고(페이지·sitemap 재생성) 커밋·배포합니다. 저에게 값만 알려 주시면 제가 넣겠습니다.

- 문의 이메일은 개인 메일 대신 전용 주소를 쓰는 편이 좋습니다(도메인 메일, 또는 새 Gmail).
- 값이 `example.com`인 동안은 구매 버튼이 숨겨지고 약관에는 `[support email]`이 보입니다. 실수로 가짜 주소가 노출되지 않습니다.

## 3. 서버 라이선스 검증 켜기 (환경변수)

1. Vercel → quickbill 프로젝트 → Settings → Environment Variables 에 두 개를 Production으로 추가합니다.
   - `LS_STORE_ID` = 1번의 스토어 ID
   - `LS_PRODUCT_ID` = 1번의 상품 ID
2. 다시 배포합니다.
3. Lemon Squeezy **테스트 모드**로 결제해 라이선스 키를 받고, 앱 업그레이드 창에 넣어 Pro가 켜지는지 확인합니다.
4. 확인 후 환불을 한 번 해 보고, 며칠 뒤(앱은 일주일에 한 번 재확인) Pro가 꺼지는지, 데이터는 남는지 확인합니다.

동작 방식: 환경변수가 없으면 기존처럼 오프라인 키(`PRO-XXXX-…`)가 동작합니다. 환경변수를 넣으면 서버가 확인한 키만 Pro가 되고 오프라인 키는 더 이상 받지 않습니다. 오프라인 상태이거나 서버가 응답하지 않아도 이미 켜진 Pro는 꺼지지 않으며, 환불·비활성화가 확인될 때만 꺼집니다. 데이터는 지우지 않습니다.

## 4. 도메인 연결

1. 도메인을 직접 구매합니다(제가 구매하지 않습니다).
2. Vercel → Settings → Domains 에서 추가하고 안내된 DNS 레코드를 등록합니다.
3. `config.js`의 `siteUrl`을 새 주소로 바꾸고 `node design/seo.cjs`를 실행한 뒤 배포합니다(canonical, hreflang, sitemap에 반영).
4. Google Search Console과 네이버 서치어드바이저에 등록하고 `사이트주소/sitemap.xml`을 제출합니다.

## 5. 사업자·세금 (확인 필요)

저는 세무 자문을 할 수 없습니다. 다음은 세무서나 세무사에게 확인하세요.

- 개인이 해외 결제 플랫폼으로 소프트웨어를 판매할 때 사업자등록이 필요한지, 언제 필요한지.
- 정산받는 수익의 소득 신고 방법(종합소득세 등).
- 통신판매업 신고 등 국내 전자상거래 관련 의무가 해당되는지.
- 이용약관의 준거법은 대한민국 법으로 적어 두었습니다. 거주 국가가 다르면 바꾸세요.

## 6. 약관·개인정보 점검

`terms.html`, `privacy.html`은 영어와 한국어 초안입니다. 법률 검토를 받은 문서가 아닙니다.

- 환불 14일 조건이 맞는지(다르면 `config.js`의 `refundDays`).
- 활성화 기기 수, 환불 시 키 비활성화 방식이 1번 설정과 같은지.
- 개인정보 페이지는 "분석 도구·쿠키 없음"으로 적혀 있습니다. 나중에 분석 도구나 결제 이메일 발송 등을 추가하면 같이 고쳐야 합니다.

## 7. 공개 전 최종 확인

- 실제 휴대폰(아이폰 Safari, 안드로이드 Chrome)에서 랜딩, 앱, 인보이스 만들기, 홈 화면에 추가를 해 봅니다. 제 환경에서는 실제 기기와 Safari를 확인하지 못했습니다.
- 인보이스를 실제로 PDF로 인쇄해 봅니다(제 환경에서는 인쇄 호출만 확인).
- 백업 JSON을 받아서 다른 브라우저에 복원해 봅니다.
- 결제 → 키 입력 → Pro → 환불 흐름을 한 번 끝까지 해 봅니다.
- 약관, 개인정보, 문의 메일 링크가 열리는지 봅니다.

## 8. 공개 순서 제안

1. 첫 유료 파일럿 5~10명 모집 (`copy.md`의 모집 문구). 가격을 받기 전에 실제 사용 후기를 모읍니다.
2. 후기 반영 후 커뮤니티 게시(한국어 → 영어). 각 커뮤니티의 자기 홍보 규칙을 먼저 읽으세요.
3. Product Hunt는 파일럿 사용자가 몇 명 생긴 뒤에 합니다.

게시와 결제 계정 생성, 도메인 구매, PR 머지는 제가 하지 않았습니다.

## 알려진 한계

- 한국 전자세금계산서와 각국 전자청구서는 지원하지 않습니다(약관과 FAQ에도 적혀 있음).
- 데이터가 브라우저에만 있어서 기기 간 동기화가 없습니다. 백업 JSON이 유일한 이동 수단입니다.
- 라이선스 서버 검증은 모의 응답으로만 시험했습니다. 실제 Lemon Squeezy 응답으로는 3번의 테스트 결제에서 처음 확인됩니다.
- 웨딩·시설 모듈은 아직 만들지 않았습니다.
